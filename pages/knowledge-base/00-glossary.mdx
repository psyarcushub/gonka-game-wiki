# Глоссарий терминов

Расшифровка всех терминов из презентации. Объяснения даны для человека, который вообще не знаком с темой. По алфавиту.

---

## A — F (английские)

### Backend инфраструктура
Невидимая часть системы, которая работает «за кулисами»: сервера базы данных, очереди задач, серверы биллинга. Пользователь её не видит, но без неё ничего не работает. Противоположность — фронтенд (то, что видит пользователь).

### CUDA
Технология компании NVIDIA, которая позволяет программам использовать видеокарту (GPU) для вычислений. Это не игры — а серьёзные расчёты для AI. Без CUDA и без правильных версий драйверов видеокарта для AI не работает. Установить CUDA — половина головной боли при настройке AI-сервера.

### Control Plane («плоскость управления»)
Центральный «штаб» всей системы. Это сервер (или несколько), который знает обо всех GPU-серверах, отдаёт им команды («запустись», «обнови протокол», «остановись»), собирает с них телеметрию и считает биллинг. Аналогия: диспетчерская в аэропорту — самолёты (ноды) летают, диспетчеры (Control Plane) координируют.

### DAO governance (DAO-управление)
DAO — Decentralized Autonomous Organization, децентрализованная автономная организация. По сути — компания, где решения принимают не директоры, а владельцы токенов через голосования в блокчейне. Governance — управление, регуляция. «Исследование governance DAO» означает: подумать, как передать часть управления платформой сообществу через токены.

### Docker
Программа для упаковки приложения вместе со всем нужным окружением в один «контейнер». Контейнер запускается одинаково на любом сервере. Это позволяет за минуты раскатывать ноды на новых машинах без головной боли «у меня тут другая версия библиотеки».

### deploy()
Английская команда, означающая «развернуть» / «запустить». В презентации `deploy()` — это функция в коде адаптера, которая запускает ноду для конкретной сети.

### Epoch (эпоха)
В блокчейн-сетях и AI-сетях — фиксированный отрезок времени (например, час или сутки), за который сеть подсчитывает вознаграждения для участников. «Вознаграждения на GPU/epoch» — сколько денег приносит одна видеокарта за одну эпоху.

### Fallback развёртывание
Запасной вариант запуска. Если основная сеть упала или нода не запускается — система автоматически переключает GPU на другую сеть, чтобы он не простаивал. См. также: [Мульти-сетевой адаптерный дизайн](/knowledge-base/05-network-adapters).

## G — N

### Governance
См. [DAO governance](#dao-governance-dao-управление).

### GPU (Graphics Processing Unit)
Графический процессор, видеокарта. Изначально создавался для рендера 3D-графики, но устроен так, что параллельно выполняет тысячи мелких вычислений — идеально подходит для тренировки AI-моделей. Серверные GPU (например, NVIDIA H100, A100) стоят $20-40 тысяч за штуку.

### Grafana
Программа, которая красиво рисует графики из данных мониторинга. Получает цифры от Prometheus и показывает их в виде дашбордов: утилизация GPU, uptime, вознаграждения. См. также: [Prometheus](#prometheus).

### Health check (проверка здоровья)
Регулярная автоматическая проверка: «Жив ли сервер?», «Видеокарта работает?», «Программа отвечает?». Если проверка проваливается — система знает, что пора рестартить или алертить оператора.

### KPI (Key Performance Indicator)
Ключевой показатель эффективности. Число, по которому понимают: «дела идут хорошо или плохо?». В презентации ключевой KPI — «утилизация GPU ≥ 70%». Если ниже — экономика не сходится.

### Liquidity (ликвидность)
Простыми словами: насколько легко продать актив (токен) и получить деньги. Высокая ликвидность = много покупателей, цена стабильна. Низкая ликвидность = продать сложно, цена скачет. «Ограничения ликвидности» = риск, что заработанные токены сложно превратить в реальные деньги.

### Mining (майнинг)
Использование вычислительной мощности для получения вознаграждения в блокчейн-сети или AI-сети. В классическом смысле — добыча криптовалюты. В контексте AI-сетей — выполнение AI-вычислений за вознаграждение в токенах.

### Mining pool
«Бассейн майнеров» — сервис, который объединяет вычислительную мощность многих участников и распределяет общие вознаграждения. Презентация специально подчёркивает: «без геймдизайна мы превращаемся просто в ещё один mining pool» — то есть в скучный бэкенд без вовлечения пользователя.

### Mini-App (Telegram Mini-App)
Маленькое приложение, которое запускается прямо внутри Telegram. Не нужно скачивать отдельную программу — нажал кнопку в чате, и открылся интерфейс. Удобно: пользователь не выходит из мессенджера. Telegram — массовая платформа, низкий порог входа для пользователя.

### MOC (Map of Content)
В контексте баз знаний — карта содержимого, оглавление с пояснениями, которое связывает заметки между собой.

### Нода (Node)
Один отдельный сервер с видеокартой, который выполняет AI-вычисления для какой-то сети. «Запустить ноду» = сконфигурировать сервер так, чтобы он подключился к сети и начал зарабатывать вознаграждения. У одного оператора может быть много нод.

### NFT (Non-Fungible Token)
Уникальный токен в блокчейне — что-то вроде цифрового сертификата на владение чем-то. «NFT инфраструктурных активов» = идея сделать ноду собственностью, представленной NFT-ом. Можно перепродавать, передавать, владеть.

## O — Z

### Onboarding (онбординг)
Процесс знакомства нового пользователя с продуктом. Регистрация, обучение, первые шаги. «Контролируемое онбординг первых пользователей» = аккуратное добавление новых игроков, чтобы не сломать экономику.

### Оркестрация (Orchestration)
Координация многих движущихся частей. Как дирижёр оркестра управляет музыкантами — так и оркестрационный слой управляет десятками/сотнями нод: где какая запущена, какую обновить, какую перезапустить. Главное слово в названии проекта.

### Parsing (парсинг)
Извлечение нужных данных из чужого формата. «Парсинг метрик вознаграждений» = разобрать ответ сети (часто в неудобном для нас формате) и достать из него: «нода Х за час заработала Y токенов».

### Production-ready (готовый к production)
«Готовый к боевой эксплуатации». То есть — стабильный, протестированный, с обработкой ошибок, мониторингом, безопасностью. Противоположность — прототип, который работает только в идеальных условиях.

### Prometheus
Программа для сбора и хранения метрик мониторинга (числовых данных) с серверов. Каждые несколько секунд опрашивает все ноды: «расскажи, как у тебя дела». Сохраняет историю — потом можно построить графики. Работает в паре с Grafana.

### Protocol (протокол)
Набор правил, по которым работает сеть. У каждой децентрализованной AI-сети — свой протокол: как подключаться, как считать вознаграждения, как обновляться. Когда «протокол обновляется», ноды должны быть обновлены, иначе их выкинет из сети.

### R&D (Research and Development)
Исследования и разработка. Фаза, на которой ты ещё не зарабатываешь — пробуешь, считаешь, проверяешь гипотезы. В презентации R&D-фаза = первые 90 дней, когда нельзя масштабироваться, пока не доказана экономика.

### Role-based access control (RBAC)
Управление доступом по ролям. Например: «администратор может всё», «биллинг-менеджер видит только финансы», «оператор может рестартить ноды, но не править код». Нужно для безопасности при росте команды.

### Стек (Stack)
Набор связанных технологий, работающих вместе. «Стек мониторинга» = Prometheus + Grafana + Alertmanager (или что-то такое) — всё вместе образует мониторинг.

### Стрим (Streaming)
Передача данных непрерывным потоком, а не порциями раз в час. «Потоковая передача телеметрии» = ноды постоянно шлют свои метрики в Control Plane, секунда за секундой.

### Telemetry (телеметрия)
Числовые данные о работе системы: температура GPU, загрузка, объём свободной памяти, скорость сети. Передаётся в реальном времени в систему мониторинга.

### TON / TMA
TON — The Open Network, блокчейн от Telegram. TMA — Telegram Mini App. Связаны: многие TMA работают с TON-кошельками.

### Токен (Token)
Цифровая «монета» в блокчейн-сети. Имеет цену в долларах, торгуется на биржах. Награждения за работу ноды обычно выплачиваются в токенах сети, на которую работает GPU.

### Unit Economics (юнит-экономика)
Экономика одной единицы. В нашем случае — одной ноды (= одного GPU). Сколько в месяц приносит и сколько съедает? Если приносит больше, чем съедает — это «положительная юнит-экономика», можно масштабироваться. Если меньше — масштабирование убьёт компанию быстрее.

### Update() / Update protocol
Обновление клиента ноды. Когда сеть выпускает новую версию протокола, все ноды должны установить новую версию своего программного обеспечения, иначе их выкинет. См. также: [Жизненный цикл ноды](/knowledge-base/04-node-lifecycle).

### Uptime
Доля времени, когда нода работает без сбоев. 95% uptime = за месяц нода может «лежать» не больше ~36 часов суммарно. Целевой uptime в презентации = 95%.

### Утилизация GPU (GPU utilization)
Доля времени, когда видеокарта реально считает, а не простаивает. 70% утилизации = из 24 часов 16.8 часов чип «работал» на полную, остальное — ждал задач. Ниже 70% = деньги тратятся впустую (аренда платится, а пользы нет).

### Validate environment (валидация окружения)
Проверка: «А подходит ли этот сервер для запуска ноды?». Есть ли нужный тип GPU? Достаточно ли VRAM? Установлены ли драйверы правильной версии? Если нет — нода не стартует.

### Vesting (вестинг)
Постепенная выдача награды. Например, вместо «вот тебе 1000 токенов сразу» — «получишь по 100 токенов в месяц на протяжении 10 месяцев». Используется, чтобы стимулировать долгосрочное участие и предотвращать массовую распродажу.

### Волатильность (Volatility)
Размах колебаний цены. Высокая волатильность = цена прыгает на 30% в день, риск большой. Низкая волатильность = цена стабильная. «Волатильность цены токена» = риск, что заработанные токены резко обесценятся к моменту вывода.

### VRAM (Video RAM)
Память видеокарты. Большие AI-модели не помещаются в маленькую VRAM. Сети могут требовать минимум 24/48/80 GB VRAM на ноду. Это критичный параметр валидации.

### Workload (рабочая нагрузка)
То, что вычисляет GPU. В AI-сетях рабочая нагрузка = AI-задачи (тренировка моделей, инференс). «Протокол = взаимозаменяемый слой рабочей нагрузки» = можно переключать GPU между разными типами задач от разных сетей.
